## ■現状（Before）

- 0929で「入口は機会損失／純増、細部は％・期間・1年フロー」と整理したあとの、支援内容の具体化提出。
- 警備員純増・離職防止・採用定着を3つにまとめ、退職エピソード・新人教育のあるある・ハロワでクライアントに動いてもらう前提、まで書けている。方向は合っている。
- What（提供価値）は良い。

```
警備員を採用して終わるのではなく、
定着させ、警備員数を純増させる仕組みを社内に作り、
機会損失を減らす
```

- 適正在籍のイメージ（例：必要実動36人 → 適正40人）はある。ただし換算の見せ方が複雑に見えやすい。社長ごとに最適人数の考え方が違う可能性もある。
- 支援内容と、浦川さんの実績・改善事例・アンケートが、同じ箱の中で混ざりやすい。
- 退職連鎖の流れは書いているが、「なぜそうなるか」「社長はどう感じるか」の因果・感情が薄い箇所がある。
- 遠方勤務の改善例は一次情報として強い。ただし「社員側の勘違いの思い込み」が読める形まで整理しきれていない。
- 1年目スケジュールの骨格はあるが、各支援を何ヶ月目に置くか、クライアント作業（特にハロワ）をいつ依頼するかがまだ弱い。
- How（集客・営業）がまだ薄い。契約に届かないとモデルが完成しない。

---

## ■問題の本質（重要）

- ビジネスモデルは **Who / What / How** で先に全体を立てる。細部のエピソードから入ると、読み手が「何を売っているのか」を見失う。
- **提供する支援内容**と**浦川さんの実績（信頼材料）**は別箱。実績はセールス前の信頼構築に使う。支援内容は「何を・どの順で・誰がやるか」を見せる。
- 適正在籍人数は、機会損失を100%取りにいく話ではない。**人が余りすぎない適正まで純増し、辞めを減らしながら穴を埋めて維持する**。社長差があるならインタビューで探る。普遍なら言い切る。
- エピソード・改善例は「事実の列挙」ではなく、**因果（なぜ）と感情（どう感じたか）と結果**まで一本でつなぐと、実績として売れる。
- スケジュールは「やる項目の一覧」ではなく、**何ヶ月目に何を提供し、何をクライアントにやってもらうか**の時系列。

## ■ズレ（思考 or 設計）

| 取れている | まだ薄い／次に足す |
|---|---|
| What＝純増の仕組みで機会損失を減らす | Who（メインターゲット／外す層）を先に固定 |
| 適正在籍のイメージ（実動＋バッファ） | 換算をシンプル化、または社長差ならインタビュー項目化 |
| やめない土台＋取れる土台 | 支援内容と実績を縦に分けて見せる |
| 退職連鎖・新人教育のあるあるの種 | 因果の接続と社長の感情 |
| 遠方勤務の改善一次情報 | 「勘違いの思い込み→把握→改善」のストーリー化 |
| アンケート・ヒアリングの存在 | 頻度・準備・アナウンス・改善の運用手順 |
| 1年目の項目一覧 | 月次配置＋クライアント作業タイミング |
| 成果報酬の骨格（0929） | 1名増員シミュレーション＋助成金を支援前に置く |
| 代行入口（0929） | How＝集客・営業の設計（エリア外含む） |

- 支援内容の箱に実績・改善例・アンケートが同居すると、横に長くなり「何を売る話か／何の証拠か」が曖昧になる。
- 内勤者が穴埋めに出る → 社長が代行 → スケジュール混乱、の因果が読者に一発で伝わらないと、「あるある」に見えない。
- ハロワは浦川さんが全部代行できない前提。**クライアントに何を・いつやってもらうか**をスケジュールに落とさないと、契約後に止まる。

## ■改善内容（What）

### 0. 先に全体整理：Who / What / How

情報を足す前に、ビジネスモデルの箱を先に立てる。

```
【Who】
・メインターゲット（例：需要過多で機会損失が出ている警備会社）
・ターゲットから外す層

【What】
・提供価値：警備員純増支援
　＝採用して終わりではなく、定着させ純増の仕組みを社内に作り機会損失を減らす
・支援内容（やること）／支援期間（1年目〜）／スケジュール

【How】
・集客どうするか
・営業どうするか（契約に結びつける流れ）
```

細部（エピソード・アンケート・改善例）は、この骨格の下にぶら下げる。

### 1. Whatを維持し、適正在籍はシンプルに

提供価値の一文は維持してよい。

適正在籍の見せ方：

| やること | ポイント |
|---|---|
| 必要実動と適正在籍の差を短く示す | 例：実動36 → 適正40（＋4のバッファ） |
| 「機会損失を100%回収しなくてよい」 | 人が余りすぎないことも重要 |
| 社長差があるか確認 | ある → インタビューで探る／ない → 答えとして言い切る |

サービス内容の核は次でよい。

```
辞めていく人を減らし、新しい人を入れ、
適正人数まで純増させて維持する
```

支援期間の言い方も維持可。「やめない土台」「取れる土台」を作り、2年目・3年目の支援内容へつなぐ。

### 2. 支援内容と実績を分ける（縦に読む）

横長の混在をやめ、**実績**と**提供内容**を別ブロックにする。

```
【実績（セールス・信頼構築用）】
・やめない仕組みづくりの実績
・警備員純増の実績
・助成金の実績

【提供内容（契約後にやること）】
・何を提供するか
・どの順でやるか（月次）
・クライアント作業は何か
```

実績は、各テーマごとに次の型で縦に並べる。

```
何をしたか
　↓
どう運用したか（頻度・準備・アナウンス）
　↓
どんな結果が出たか（会社側／警備員側）
```

バディ制度・退職予兆の早期把握・入社初期のフォロー体制は、実績側に寄せてよい。

### 3. 退職連鎖：因果と感情を一本にする

導入前の問題点は、事実の羅列で止めず、接続を明示する。

**推奨の因果（要検証・実態に合わせて直す）：**

```
急な退職が出る
　↓
内勤者が現場の穴埋めに出る
　↓
内勤者がやっていたスケジュール管理が回らなくなる
　↓
社長が代行し、自分の予定を再調整させられる
　↓
他の警備員の希望シフトが崩れ、負担・不満が増える
　↓
さらに退職・支援要請の連鎖が起きる
```

足すもの：

| 足りない要素 | 書く内容の例 |
|---|---|
| 社長の感情 | そのとき社長はどう感じるか |
| 再調整の具体 | どんな予定が犠牲になるか |
| 「なぜ俗人化／混乱するか」 | 内勤が穴埋めに出た結果、誰が管理できなくなるか |
| 内勤が複数いる場合 | それでも問題が起きる条件／起きない条件 |

「スケジュール管理が俗人化する」だけで止めず、**他の警備員に何が起き、なぜ不満が退職につながるか**までつなぐ。

### 4. 遠方勤務の改善例：「勘違いの思い込み」を前面に

この事例は一次情報として非常に強い。整理の軸は次。

```
【社員側の思い込み】
遠方ばかり続いて、自分だけ負担が大きいのでは

【会社側の実態】
遠方が多い人を把握し、余裕がある日は優先して休みにしていた

【改善の本質】
勘違いに気づき、配置の意図を共有できるようになった
```

「不満を聞いた」「配置を見直した」だけだと弱い。**思い込みのズレが可視化され、理解が進んだ**ところまで書く。

イベント警備（土日希望が難しい等）も、理由が分からない一文は残さない。なぜ難しいかを1行足す。

### 5. アンケート／ヒアリングを運用手順にする

退職予兆の早期把握は、次を埋める。

```
・頻度（毎月／2週間に1回／2ヶ月に1回 など）
・事前準備（何を用意するか）
・アナウンスの仕方
・ヒアリング／アンケート後のサポート
・改善の進め方
・得られたメリット（会社側／警備員側）
```

「アンケートがある」ではなく、**どう回して、どう改善に使うか**が実績になる。

### 6. 1年目スケジュール：月次＋クライアント作業

支援内容のざっくり流れを、月次に落とす。

```
開始前：現状把握・シミュレーション
1ヶ月目：退職予兆の早期把握（運用開始）
2ヶ月目〜：ターゲット設定（同時進行可）
以降：ジョブリスティング／ハロワ／定着／助成金
入社初期フォロー・バディ：何ヶ月目に入れるかを明示
```

ポイント：

- LINEステップをベースに採用の仕組みをつくる、で一向に進めてよい
- ステップ後半からジョブリスティングだけでなくハロワも入れる、と明記
- **毎月の打ち合わせ（例：月1）**と、自社リサーチが必要な回（2〜3回）を分けて書く
- ハロワはクライアントが動かないと進まない。**何ヶ月目から・何をやってほしいか**をスケジュールに書く

### 7. 助成金・純増・成果シミュレーション

| 箱 | 入れるもの |
|---|---|
| 実績：助成金 | 何の助成金か／いくら規模か／どう使えたか |
| 実績：純増 | 適正在籍の決め方（浦川さんがどう落としたか）→施策→結果 |
| コンテンツ（支援前） | 1名増員の経済シミュレーション＋助成金込み |
| 実例ストーリー | やめない仕組み → 穴を防ぐ → 純増 → ハロワで応募 → 助成金 → 利益 |

シミュレーションは支援内容の説明より前に置くと、「ノーリスクでそれが回る」への橋が短くなる。

### 8. How：集客と営業を必ず書く

契約に届かないとモデルは完成しない。山本側で用意できる部分はあるが、浦川さん自身も把握する。

```
・集客はどうするか
・営業はどうするか
・居住エリア外からどう集めるか（浦川さんの制約）
```

整理の優先順位は、まず What／実績／スケジュールを固める。その直後に How を埋める。

## ■改善理由（Why）

- Who / What / How を先に立てないと、エピソードが増えるほど「何のビジネスか」がぼやける。0929で入口ラベルを整えた続きとして、今回は**箱分けと時系列**が本題。
- 実績と支援内容を混ぜると、セールスでは証拠が薄く見え、契約後説明では手順が薄い。役割が違う情報は箱を分ける。
- 警備会社の社長は、抽象の「仕組み」より、**退職が会社に何を起こすか／1名増えたらいくら効くか**で動く。因果・感情・シミュレーションはそのため。
- 適正在籍を複雑に見せると、機会損失の話が「計算パズル」になる。シンプルな差（実動とバッファ）と、社長差の扱いを決めた方が売れる。
- ハロワは代行しきれない工程がある。クライアント作業を月次で示さないと、0911・0929で立てた代行モデルが現場で止まる。
- How がないと、良い What でも契約が生まれない。エリア外制約がある浦川さんほど、集客・営業の設計は必須。

## ■改善後イメージ（After）

読み手が次の順で理解できる状態。

```
1. 誰に売るか（Who）／何を売るか（What）／どう契約まで持つか（How）
2. 提供価値は「純増の仕組みで機会損失を減らす」
3. 適正人数まで純増・維持する（計算は短く）
4. 実績3本（やめない／純増／助成金）で信頼
5. 支援の月次スケジュールとクライアント作業
6. 1名増員＋助成金のシミュレーション → 成果報酬でノーリスク、へ接続
```

退職エピソードは、事実 → なぜ → 社長の感情 → 連鎖、まで音読で止まらない。  
遠方勤務の改善は、「思い込みのズレが解けた」事例として一瞬で伝わる。  
アンケートは頻度・回し方・改善まで書いてあり、再現可能な運用に見える。

---

## ■やりがちなミス

- エピソードや改善例を増やしたのに、Who / What / How の骨格が後回し
- 実績と支援内容を同じ見出しの下に横長で並べ、役割が混ざる
- 「内勤が穴埋め」「社長が代行」と書いて、接続（なぜスケジュールが崩れるか）を省略する
- 社長の感情・犠牲になる予定を書かず、事務的な問題列挙で終わる
- 遠方の改善で「聞いた・直した」だけ書き、「勘違いだった」が消える
- アンケートの存在だけ示し、頻度・アナウンス・改善手順がない
- 1年目の項目一覧はあるが、何ヶ月目かが空欄
- ハロワを支援内容に入れつつ、クライアント作業タイミングを書かない
- 助成金を「ある」とだけ書き、種類・金額感がない
- 良い What のまま How（集客・営業）を白紙にする
- 適正在籍の換算を複雑にしたまま、社長差の扱いを決めない

## ■他の案件でも使えるパターン

### パターンA：ビジネスモデルは Who / What / How から

```
Who（誰に／外す誰）
What（何を提供／期間／スケジュール）
How（集客・営業）
→ その下に実績・エピソード・運用手順
```

### パターンB：実績と提供物は別箱

| 箱 | 用途 |
|---|---|
| 実績 | 信頼・セールス前 |
| 提供内容 | 契約後にやること |
| コンテンツ（シミュレーション等） | 価値の可視化・クロージング前 |

### パターンC：問題エピソードは因果＋感情

```
出来事 → なぜ起きる → 誰がどう感じる → 連鎖結果
```

### パターンD：改善一次情報は「思い込みのズレ」

```
相手の思い込み → 実態 → ズレに気づく → 改善
```

### パターンE：運用系施策は頻度まで落とす

アンケート・面談・定例は、存在するだけでなく **頻度・準備・アナウンス・改善** の4点をセットにする。

### パターンF：代行モデルでもクライアント作業は月次で明示

自分だけでは完結しない工程（ハロワ申請・社内協力など）は、スケジュール上の「クライアント作業」行を必ず持つ。

## ■一言まとめ（本質）

👉 支援のパーツを増やす前に、Who / What / How で箱を立て、実績と提供内容を分け、月次とクライアント作業まで時系列にする。エピソードは因果と感情までつなぐ。

- 今回：その **What／1年フロー／実績化／シミュレーション** を具体の情報設計に落とし込む回。
