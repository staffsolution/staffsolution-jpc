## ■分類（タグ）

- ビジネスモデル設計（警備業・成果報酬）
- 入口訴求は「求人内製化」ではなく「機会損失／警備員純増」
- 価値提供＝採用の仕組みづくり（求人＋定着＋助成金）
- 入口は代行、内製化は後出しオプション
- 成果報酬の％・粗利定義・支援期間（1年更新／買い取り3年）
- 1年分の代行スケジュール（LINE・ハロワ・定着・助成金）
- 自社ビフォーアフター（ネタ化）
- 社員インタビュー追加（ターゲット精度）
- 0911・0824の続き／0927シェア会後の整理

---

## ■現状（Before）

- 富山リアルシェア会後、ビジネスモデル案をまとめた提出へのフィードバック。
- 「提供できるサービス価値は見えてきた。細部の決め方がわからない」状態。方向は合っている。
- 社員インタビューは社長＋複数名。3人目も協力見込み。4人目・5人目まで取れるなら取る。
- 案の中に「求人内製化」が前面に出やすい。一方、欲求の核は「警備員を順調に純増させたい／機会損失をなくしたい」。
- 成果報酬の骨格（初期0・採用できなければ0・利益・助成金が入ったら一定割合）はある。％・粗利から何を差し引くか・支援期間は未確定。
- 代行範囲（LINEステップ等）と、何ヶ月で何をするかの流れがまだ一覧になっていない。
- 定期アンケート／ヒアリングは案に入っており、評価できる。

---

## ■問題の本質（重要）

- **山本の求人内製化ビジネス**と、**浦川さんの成果報酬型・代行ビジネス**は、入口の売り方が違う。浦川さんの前面は「人手不足で取りこぼしている利益を一緒に取りにいく」。内製化は必須ではなく、ニーズがある相手への後出しでよい。
- 提供価値のラベルは「求人内製化支援」より、**警備員純増／採用の仕組みづくり**の方が相手の欲求に直結する。採用の箱の中に、求人・定着率アップ・助成金が入る。
- 入口は**代行**。社長・社員に最初からやらせない。結果が出たあと、「自社でも回したい」と言われたときだけレクチャーする。
- 細部で詰めるべきは感情論ではなく、**％・粗利定義・期間・権限・1年スケジュール・自社事例のビフォーアフター**。ここが数字と時系列で揃うと、契約と説明が一本になる。

## ■ズレ（思考 or 設計）

| 取れている | まだ薄い／次に足す |
|---|---|
| 機会損失を減らす、というコンセプト | 入口コピーから「求人内製化」を外す |
| 成果報酬（初期0）の骨格 | ％・粗利の差し引き項目・何年スパン |
| 代行したい相手がいる（0911） | 内製化はオプション扱いと明文化 |
| 定期ヒアリング | 自社のBefore→施策→Afterをネタ化 |
| 9ステップをベースにできる | 対外は「1年目／2年目／3年目」で見せる |
| 支援期間の感覚 | 1年更新／内製化希望時の買い取り3年／権限の扱い |

- 「内製化したい会社」も「ずっと代行してほしい会社」も両方あり得る。どちらか一方に決め打ちしない。
- 依存が起きる可能性はある。成果と報酬が大きければ関係は続きやすい。依存を悪者にしすぎず、**権限・買い取り・更新**で設計する。

## ■改善内容（What）

### 0. 維持してよい点

```
【良い】
・機会損失／利益シェアのコンセプトは0911・構想メモと一貫している
・成果報酬の入口（初期0・取れなければ0）はターゲット（採用費ゼロ層）に合う
・定期アンケート／ヒアリングが入っている（ネタと改善の両方に効く）
・社員インタビューを増やせる余地がある（ターゲット精度が上がる）
```

細部が未確定なのは問題ではない。次は「決めるリスト」を埋める段階。

### 1. 入口訴求：求人内製化は前に出さない

メインターゲットの欲求は次。

```
警備員を順調に純増させたい
　↓
機会損失をなくしたい
　↓
そのサポートに入る
```

求人内製化は、結果が出せるようになったあと、社内で回すイメージがつく相手にだけ。セミナーや個別相談で「内製化もできます」と伝え、ニーズがある人だけ支援する。ニーズがなければ、長期のお付き合い（代行継続）でよい。

**推奨ラベル例：**

| 弱い（入口向きでない） | 強い（入口向き） |
|---|---|
| 求人内製化支援 | 警備員純増のための仕組みづくり |
| 9ステップ実践支援 | 採用の仕組みづくり（求人・定着・助成金） |

### 2. 提供の型：入口は代行 → 必要ならレクチャー

```
【基本】
浦川さんが代わりにやる（代行）
　↓
山本が都度チェックしてもよい
　↓
結果につなげる

【オプション】
「自社内で軌道に乗せたい」と言われたとき
　↓
やり方をレクチャーする（内製化支援）
```

最初から「社長・社員が取り組む」設計にしない。

### 3. 自社ネタ：Before → 仕組み → After

取り組み前と後の変化を、浦川さんの会社で出す。多くの警備会社の「あるある」と重なる。

```
【Before】
雇ってもすぐ辞める／理由がわからない、など

【施策】
その問題を解くために、この仕組みを入れた

【After】
その結果、こうなった（人数・定着・受注・費用など）
```

数字が入ると、セミナー・提案・LPの証拠になる。

### 4. 成果報酬：％と粗利定義を浦川さん側で出す

骨格は維持してよい。

```
初期費用0
採用できなければ0
採用した人が利益を生む
採用関連の助成金が入金された場合も含め
経営利益（粗利）の一定割合を報酬にする
```

次に埋めること：

| 決める項目 | メモ |
|---|---|
| 何％なら自分が納得できるか | 警備経営者としての肌感で出す |
| 粗利から差し引く経費 | 広告費は差し引き対象。他に何を引くか |
| 機会損失を何年スパンで最大化するか | 1年目／2年目／3年目の到達イメージ |

広告費はクライアント負担。仕組みはこちらが作る。

### 5. 支援期間・権限・買い取り

内製化を必須にしないなら、最初から「3年必須」にしなくてよい。

**案（詰める用）：**

```
【通常】
支援期間は1年ごと自動更新
やめることはできる、と伝えてよい

【権限】
リスティング等は閲覧のみ（いじれない）
LP・設定・データをこちらが持つと、実質は継続利用になりやすい

【内製化・買い取り希望のとき】
その時点からレクチャーを開始
例：3年後に全権限をお渡し
3年以内の契約解除は不可、など（買い取り型）

【ずっと代行希望】
自動更新（年1）で継続
```

道場さんに「リスティングの権限付与をどうしているか」を確認するとよい。情報が入り次第、モデルに反映する。

### 6. 1年スケジュール（代行の流れ）

目安は約6ヶ月で一通り代行し、1年かけて費用対効果を最大化する、という見せ方。

山本が以前やっていた目安（テンプレ化できている浦川さんなら近いペースで可）：

```
1ヶ月目：ターゲット設定・競合リサーチ・自社リサーチ
2ヶ月目：ポジショニング・スタッフインタビュー
3〜4ヶ月目：コピーライティング（＋LP着手）
5ヶ月目：LP完成
6ヶ月目：リスティング開始
```

対外説明では「9ステップ」より、次を一覧にする。

```
・LINEステップ代行（どの月に何をするか）
・ハロワ活用（いつ入れるか）
・定着率アップ（いつ・何をするか）
・助成金（いつ・何をするか／社労士提携）
・クライアント負担費用（広告費など）
・2年目・3年目に何が続くか
・継続サポートが必要な理由（費用対効果が落ちる／ハロワを止められない、等）
```

協力体制の有無で期間は伸び縮みする、と先に伝える。

助成金は全国対応・助成金特化の社労士と提携する。求人内製化で関わっているアクセルさんとの提携も選択肢。

### 7. 社員インタビューは取れるだけ取る

3人目が協力するなら実施。4人目・5人目も可能な人は聞く。メインターゲットの妥当性、「省くべき社長像」がはっきりする。

### 8. 進め方

細部はグルコンで詰めつつ、浦川さん・山本・AIの壁打ちで進める。メンバーからのアイデアも取り入れてよい。

## ■改善理由（Why）

- 入口を「求人内製化」にすると、山本の商品と混ざり、相手の本音（人数・機会損失）から一段ずれる。
- 代行先行は、0911の「採用費ゼロ・代行関心・媒体不信」層に入るため。最初から内製化を必須にすると、動けない会社が落ちる。
- ％・粗利・期間・権限は、契約と説明の骨格。ここが曖昧だと成果報酬が「きれいな話」で止まり、現場で結べない。
- 自社ビフォーアフターは、提案の証拠と、ターゲットあるあるの両方になる。
- 1年スケジュールがあると、「何をいつやるか」が相手にも自分にも見える。協力の遅れ＝期間延長、も説明しやすい。

---

## ■改善後イメージ（After）

- 提案の正面が「警備員純増／採用の仕組みづくり」になっている。求人内製化は後出しオプション。
- 入口は代行。内製化希望が出てからレクチャーが始まる。
- 成果報酬の％・粗利の差し引き・1年更新／買い取り3年の扱いが一覧になっている。
- LINE・ハロワ・定着・助成金・費用が、1年目（と2・3年目）の時系列で並んでいる。
- 自社のBefore→施策→Afterが数字付きで語れる。
- 社員インタビューが増え、メインターゲットと「お断りする社長像」がはっきりしている。

---

## ■やりがちなミス

- 入口から「求人内製化」を前面に出し、機会損失の話が後ろに下がる。
- 内製化を必須にして、ずっと代行してほしい会社を切り捨てる（またはその逆だけにする）。
- 成果報酬の％と粗利定義を決めず、コンセプトだけで進める。
- 支援期間を決めずに、権限だけ渡す／渡さないが曖昧になる。
- 対外説明に「9ステップ」をそのまま出し、クライアント側の言語にしない。
- 自社の成功談だけ語り、Before（辞める・理由不明など）を書かない。
- スケジュールなしで「だいたいやります」になり、協力不足時の延びに説明がつかない。

## ■他の案件でも使えるパターン

### パターンA：自分の商品と相手の欲求のラベルを分ける

```
自分が得意な手法の名前（求人内製化・9ステップ）
　≠
相手が払う理由の名前（純増・機会損失・採用の仕組み）
```

入口は後者。前者は後から出す。

### パターンB：代行 → オプションで内製化

```
まず代わりにやる
　↓
結果が出る
　↓
「自社でも回したい」が出たらレクチャー
```

### パターンC：成果報酬は％より先に「粗利の定義」

```
何％か
＋
何を差し引いたあとの数字か
＋
何年分の支援か
```

3つが揃って初めて契約設計になる。

### パターンD：継続は権限と更新で設計する

```
閲覧のみ／データはこちら
　↓
自動更新で続きやすい
内製化希望
　↓
レクチャー＋買い取り（年数・解除条件）
```

### パターンE：証拠は自社のBefore→After

```
多くの会社の「あるある」＝自社の以前
　↓
仕組み
　↓
今の数字
```

## ■0911・0824・構想メモとの関係

| 過去・資料 | 今回（0929）との接続 |
|---|---|
| **0911** 成果報酬・初期ゼロ・うまくいく会社だけ | 今回はその**売り方をビジネスモデルの細部（％・期間・代行フロー）に落とす**回 |
| **0824** 外部に頼んででも解決したいターゲット | 入口を内製化にしない判断と一致。代行先行がそのまま当てはまる |
| **0908** キープ型 | 今回のモデルの主戦場ではない。選別で外す側 |
| **構想メモ（0926）** 利益シェア型 | コンセプトは維持。今回は内製化の位置づけと運用設計の具体化 |

0911が「誰に・何のオファーか」。今回は「そのオファーをどう運用し、どう契約設計するか」。
