## ■現状（Before）

- 高卒採用に絡めたプロフィールを提出。これまでの経験は書けている。
- ただし中身は**「今までやったこと」の列挙**に近い。「講座としてこれを伝えたい。だからこの経験を使う」という前提が先にない。
- そのため、プロフィールのどこを残し、どこに落とすかが決まらない。
- AIとの壁打ちでは、核として**仕組みづくり**が出ている（山内さんは仕組みづくりに長けている、という仮説）。
- 事業側では、講座シナリオやプロフィール完成に寄りがちだが、**今のタイミングで講座を開催する段階ではない**（成果事例シェア会でも、以前から同じ指摘）。実績を直接積むフェーズである。

---

## ■問題の本質（重要）

- コピーも自己紹介もストーリーも同じ。**「これを伝えたい」が先**。そのために経験のどの部分を使うかを決める。やってきたことの棚卸しが先だと、高卒採用に落ちない。
- プロフィールの一本線は、**SE・業務改善で「現場の問題を仕組みに変えてきた」→ その精度があるから高卒採用の仕組みも作れた**、である。
- 今やるべき優先順位は、講座シナリオではなく**高卒採用のビジネスモデルを組むこと**。プロフィール整理は、集客・セールスで使う材料として後から効く。
- ビジネスモデルの核は**誰に（最重要）→ 何を → どのように**。最初はターゲットを一人に絞る。サービスは競合を調べて真似し、**オファーを強くしてハードルを下げ、実績を積む**。先生ポジションは、最低5件（できれば10件前後）のあとに来る。

| 意図 | 結果 |
|---|---|
| プロフィールで信頼を取る | 経験の羅列になり、「伝えたいこと」が見えない |
| 高卒採用講座の準備を進める | シナリオ・プロフィール先行で、**実績とビジネスモデルが後回し** |
| いろんな経験を見せる | 仕組みづくりへの特化がぼやける |
| 自分でサービスを一から考える | 競合を見て真似→強いオファー、の方が速いのに遠回りしやすい |

- 0814は「希望が先／独立理由」。今回はその先で、**伝える核（仕組みづくり）を決め、講座よりビジネスモデルと実績を優先する**段階である。

## ■改善内容（What）

### 1. プロフィール：伝えたいことを先に決める

フィルターを1文で決めてから、経験を抜粋する。

```
このプロフィールで伝えたいこと：
「現場の問題を仕組みに変えてきた。
　その経験があるから、高卒採用の仕組みも作れた」
```

推奨の骨格：

```
20年以上、現場の問題を仕組みに変えてきた
（システム開発・SE・業務改善）
　↓
現場の問題を聞き、解決する仕組みを作ってきた
　↓
その経験値があるから、精度の高い仕組みを作れる
　↓
同じやり方を高卒採用にも応用した
```

「今までやったこと」の一覧は載せない。上の線に沿う部分だけ残す。

### 2. 今の優先：講座シナリオではなくビジネスモデル

| 今はやらない（後回し） | 今やる |
|---|---|
| 高卒採用講座のシナリオ完成 | ビジネスモデルを組む |
| 講座開催の準備 | 直接お客を取り、実績を積む |
| プロフィールの完璧化だけ | プロフィールは集客・セールス用に整える |

プロフィール整理は無駄ではない。**ビジネスモデルで集客・セールスするときに使う**前提で整える。

### 3. ビジネスモデルの型（誰に／何を／どのように）

浦川さんへのフィードバックと同型。最初に埋める項目：

```
誰に（最重要・最初は1人に絞る）
　├ メインターゲット（ピンポイントで「ここならめちゃくちゃ役に立つ」）
　└ サブは後でよい

何を
　├ どんなサービス・商品か
　├ 価格帯
　└ 期間

どのように
　├ 見込み客の獲得方法
　├ セールス方法
　└ 提供の進め方
```

「誰に」が一番重要。最初から複数ターゲットに広げない。

### 4. サービス設計：競合リサーチ → 真似 → 強いオファー

1. 「高卒採用」「高卒採用 支援」などで競合サービスを一通り洗う
2. 情報を整理し、**どこが最も売れているか**を見る
3. メインターゲット／サービス内容／価格／期間／販売の流れを競合から学ぶ
4. サービス内容は**競合のパクリでよい**。差はオファーの強さでつける
   - 価格を安くする／手厚くする、など依頼のハードルを下げる
5. 強いオファーで件数を積み、経験を講座に反映する

### 5. 見込み客・セールス

| 項目 | 方針 |
|---|---|
| 見込み客 | JLC内に高卒採用ニーズがある。環境を活かす |
| セールス | **個別相談の一択** |
| セールスの型 | **SPIN営業術**（質問するセールス）を熟読して使う |
| オファー | サービス内容を伝えきれる強さにする |

独立後に必須のセールススキルを、この実績作りの中で身につける。

### 6. 実績の目安（講座の前）

- **最低5件以上**ないと、講座で伝える説得力が弱い
- **10件前後**あると、先生ポジションが取りやすい
- 件数を積む過程でカリキュラムの中身も良くなる

### 7. 進め方（ドロクサク）

1. ビジネスモデル（誰に／何を／どのように）を1枚にまとめる → フィードバック可
2. 競合を洗い、サービスとオファーを決める
3. JLCで見込み客にアプローチし、個別相談（SPIN）で顧客化する
4. 実績5〜10件を積み、そのあと講座

見込み客獲得で多くの人はつまずくが、JLCには候補がいる。ここを活かす。

### 8. マインドマップ用（コピペ）

```
0825差し替え：伝えたいこと → 仕組みづくり → BM → 実績 → 講座

├ プロフィール
│  ├ 伝えたいこと（先に1文）
│  ├ 現場の問題を仕組みに変えてきた（20年超）
│  └ だから高卒採用の仕組みも作れた
│
├ 今の優先（講座シナリオは後）
│  ├ ビジネスモデル（誰に／何を／どのように）
│  ├ 競合リサーチ → パクリ → 強いオファー
│  └ JLCで見込み客 → 個別相談（SPIN）
│
└ 実績のあと講座
   ├ 最低5件（理想は10件前後）
   └ 経験をカリキュラムに反映
```

## ■改善理由（Why）

- 「伝えたいこと」が先にあると、プロフィールは履歴書ではなく、**高卒採用の先生としての一本線**になる。
- 仕組みづくりに特化すると、SE経験の広さが「何屋かわからない」から「再現可能な仕組みを作る人」に変わる。
- 実績が少ない段階で講座に寄ると、説得力と再現性が足りない。強いオファーで件数を取る方が、あとで講座が自然になる。
- 「誰に」を絞らないと、サービスもセールスもぼやける。競合を見れば、誰に何をいくらで売っているかの型が見える。
- セールスは個別相談＋SPINに寄せると、型が増えすぎない。JLCに見込み客がいるので、獲得の入口で止まりにくい。

---

## ■改善後イメージ（After）

- プロフィールを読むと、「仕組みを作る人」だと一瞬で分かる。高卒採用への接続が自然。
- 手元の仕事の中心が、講座シナリオではなく、**誰に何を売るかのビジネスモデルと顧客獲得**になっている。
- 競合を見たうえでサービスがあり、オファーが強く、依頼のハードルが下がっている。
- JLC経由の個別相談（SPIN）で件数が増え、5件→10件と実績が積み上がっている。
- その経験が、将来の講座の中身になっている。

---

## ■やりがちなミス

- 経験を全部載せようとして、「伝えたいこと」を決めない。
- 仕組みづくりと言いながら、特化と関係ない経歴を同じ分量で並べる。
- ビジネスモデル（誰に）を決めずに、講座シナリオやプロフィールだけ直す。
- ターゲットを最初から複数に広げる。
- 競合を見ずに、ゼロからサービスを考え続ける。
- オファーを弱いままにして、実績が1件で止まる。
- 実績5件未満で「先生」として講座を開こうとする。
- 見込み客を外に探し続け、JLCの環境を使わない。
- セールス手法を増やしすぎて、個別相談＋SPINに絞れない。

---

## ■他の案件でも使えるパターン

- **伝えたいことを先に1文。** 経験はその抽出に使う。
- **専門性は「何をしてきたか」より「どんな問題を仕組みに変えたか」で示す。**
- **教える（講座）より先に、売る（ビジネスモデルと実績）。**
- **誰にが最重要。最初は1人。**
- **サービスは競合を真似し、差は強いオファーでつける。**
- **セールスは個別相談＋質問型（SPIN）に寄せる。**
- **先生ポジションは件数のあとに来る（目安5〜10件）。**
