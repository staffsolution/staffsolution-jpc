## ■現状（Before）

- 0814で指摘した「希望が先／独立理由」の続き提出。これまでの経験・独立を選んだ理由は一通り書けている。
- ただし**たくさんのことを伝えようとしていて、結局何を伝えたいかが定まっていない**。そのため読み手に残りにくい。
- 「身につけた力」と「退職理由」と「転職の経緯」が**一本につながっていない**。待遇面の話に寄り、職場環境の具体事例がないので、どんな問題があったのか感情移入しにくい。
- 「長く働き続けることは難しい」という判断も、**どのような問題があってそう思ったのか**が見えないと、人となりが見えてこない。
- システム担当のお客様から「今後も支えてほしい」と誘われ社内SEへ、は**信頼されていた証拠として使える**。だが、そこでどのくらい働いたか、何をしていたか、辞めるまでの経緯が載っていない。
- SEからシステム開発まで幅広くやってきたのは分かるが、**何に特化しているのか**が分からない。特化なしで多く並べると、高卒採用講座への接続が弱くなる。
- パソコンとの出会い〜システム開発の流れに、**思考・価値観が一気に変わったターニングポイント**が感じ取れない。
- 独立を選んだ理由も、「本当にこれで独立したの？」と感じる水準で、リアリティが足りない。
- 講座前提でプロフィールを厚くしているが、**実績はまだ1件**。前回シェアした事例も、選ばれた大きな理由が「家が近かった」寄りだった。

---

## ■問題の本質（重要）

- プロフィール・ストーリーの鉄則は、**やってきたことを羅列することではない**。先に「このプロフィールを通じて何を伝えたいか」を決め、それに沿う情報だけを抜粋する。
- 高卒採用に接続するなら、経歴の核は「何社で何をしたか」ではなく、**現場の問題を仕組みに変えてきた専門性**である。誰がやっても同じ成果が出る状態へ持っていく力を、SE／社内SEの仕事で身につけ、それを高卒採用に転用した、という一本線にする。
- 生々しいエピソードの骨格は、**問題 → 何を学んだか → 次にどう改善しようとして動いたか**。待遇・環境のラベルだけでは人となりは出ない。
- 講座は、再現できる仕組みと複数実績のあとに置く。今の段階の優先は、**ビジネスモデル（誰に・何を・いくら・どの期間・どのステップ）を固め、代行などで実績を積み、その過程でカリキュラムを良くすること**である。

## ■ズレ（思考 or 設計）

| 意図 | 結果 |
|---|---|
| 経験・スキル・独立理由を厚く書く | 情報が増え、**伝えたい一本線が消える** |
| 退職・転職の経緯を説明する | 待遇・環境の抽象語で止まり、具体と学びが見えない |
| 「お客様からの信頼→社内SE」を書く | きっかけだけで、在籍中の内容・辞める経緯がない |
| いろんな仕事をしてきた実績を見せる | 特化が見えず、高卒採用への接続が弱い |
| プロフィールを講座用に完成させたい | 実績1件の段階で講座前提になっており、**ビジネスモデルと実績作りが後回し** |
| 独立理由を書く | リアリティが薄く、「本当にこれで独立したのか」と感じる |

- 0814は「希望が先／独立してどうなりたかったか」。今回はさらに、**伝える核（仕組み化）を決め、それ以外を削る**段階である。同時に、講座より先にサービス設計と実績、という事業側の順番も入れ替える。

## ■改善内容（What）

### 0. 先に決めるもの（伝えたい一本線）

羅列の前に、次を1文で決める。これが全ブロックのフィルターになる。

```
このプロフィールを通じて伝えたいこと：
「現場の問題を、誰がやっても同じ成果が出る仕組みに変えてきた。
　そのやり方を高卒採用にも転用できる」
```

この線に沿わない経歴・スキル・エピソードは、たとえ事実でも載せない（または短く後ろへ）。

### 1. 経歴の核を「仕組み化の専門性」に落とす

推奨のストーリー骨格：

```
SE／社内SEの仕事で、
現場の問題に取り組むたびに仕組み化し、体系化した
（誰がやっても同じような成果が出る状態へ）
　↓
その力を、20年以上の現場で積み上げてきた
　↓
初めて高卒採用を担当したとき、方法ゼロで失敗した
（何を考えていたか／なぜ失敗したか／何に気づいたか）
　↓
やり方を見直し、同じ「仕組み化」を高卒採用に当てはめた
　↓
自社で一件成功。独立後も件数を重ね、再現できる形に改善してきた
　↓
同じ問題を抱える会社に、そのやり方を届けたい
```

「パソコンとの出会い」などは、この線を補強するときだけ残す。広く経歴を並べるためだけの導入にはしない。

### 2. 退職・転職・社内SE：生々しさと学びを足す

残す／削るの目安：

| 残す | 削る／抽象のままにしない |
|---|---|
| 具体の問題（何が起きていたか） | 「待遇」「職場環境」だけのラベル |
| 問題から何を学んだか | 感情移入できない一般論 |
| 次にどう改善しようとして動いたか | 「長く続けにくい」だけで終わる判断 |
| お客様からの信頼（今後も支えてほしい） | 誘いの一文だけで終わる書き方 |
| 社内SEでの取り組み・在籍の長さ・辞める経緯 | 信頼エピソードの切り捨て |

壁打ち用の問い：

- 長く続けにくいと判断したとき、目の前で何が起きていたか
- その問題から何を学び、次の会社／独立でどう変えようとしたか
- 社内SEでは何年・何をして、なぜそこを離れたか

「その場その場で動いただけ」に見える書き方は、読み手にデメリットになる。学びと次の行動まで書く。

### 3. 独立理由：リアリティのある情報に差し替える

0814の「どうなりたかったか」に加え、今回は**信じてもらえる具体**を足す。

- 独立を決断した直前に、何が決定打だったか
- 「仕組みで現場を変える」仕事を、自分の事業としてやる、と腹落ちした瞬間はいつか
- 高卒採用で方法ゼロ→失敗→仕組み化で成功、が独立後の路線とどうつながるか

「本当にこれで独立したの？」を潰すのは、立派な使命文ではなく、**そのときの判断材料の具体**である。

### 4. 講座より先：ビジネスモデルと実績

プロフィールを講座用に完成させるより、次の順を優先する。

1. **サービス設計**（講座より代行・支援サービスが先）
   - 誰をターゲットにするか
   - どんなサービスか／価格／期間
   - どのステップで進めるか
   - クライアントは何をするか
2. **実績を複数つくる**
   - 「家が近い」以外の理由で選ばれる状態を、何件も作る
   - その過程で仕組みとカリキュラムを良くする
3. **そのあと講座**
   - 再現できるやり方と実績が揃ってから、初めて講座が自然になる

今は1件だけなので、講座スタートの段階ではない、という前提で動く。

### 5. リサーチの進め方（すぐ着手）

| やること | 目的 |
|---|---|
| JLC内の「高卒採用をやりたい」見込み客へ直接アプローチ・インタビュー | 欲求・目指す状態を掴む |
| 高卒採用の支援サービスを出している競合をリサーチ | 他社の中身を知り、勝てる路線を決める |
| 高卒採用の書籍を読み込む（未読分） | 言葉と論点の解像度を上げる |
| 上記を踏まえて自社サービスを言語化する | ビジネスモデルのたたき台にする |

最初の目標は、「見込み客の情報を集め、顧客化し、実績を作り、仕組みを強化する」ことに置く。

### 6. マインドマップ用（コピペ）

```
0825：伝えたい一本線 → 仕組み化 → 実績 → 講座

├ プロフィールの核
│  ├ 伝えたいこと（先に1文）
│  ├ 現場の問題を仕組みに変えてきた（20年超）
│  ├ 高卒採用：方法ゼロ→失敗→気づき→仕組み化→成功
│  └ 独立後：件数を重ね再現性を上げる
│
├ 経歴の肉付け
│  ├ 問題の具体 → 学び → 次の改善行動
│  ├ お客様からの信頼→社内SE（期間・内容・辞める経緯）
│  └ 特化以外の羅列は削る
│
└ 事業の順番（講座より先）
   ├ サービス設計（誰・何・いくら・期間・ステップ）
   ├ 見込み客インタビュー（JLC内も可）
   ├ 競合リサーチ
   ├ 代行等で実績を複数（近さ以外の理由で選ばれる）
   └ 仕組み強化のあと講座
```

## ■改善理由（Why）

- 伝えたいことが先にあると、経歴は「履歴書の厚み」ではなく、**読み手が覚える一本の物語**になる。コピーでストーリーを使うときの鉄則でもある。
- 「仕組み化」に特化すると、SE経験の広さが弱み（何屋かわからない）から、強み（現場を再現可能な形に変える人）に変わる。高卒採用への接続も自然になる。
- 待遇・環境のラベルだけでは感情移入できない。問題→学び→次の行動があると、0814で求めた**人となり**が出る。
- お客様からの信頼エピソードは、特化ストーリーの証拠になる。期間・内容・辞める経緯まで書くと、転職が点ではなく過程になる。
- 実績1件・「家が近い」理由が強い段階で講座を出すと、再現性と説得力が足りない。代行で件数を積み、仕組みを良くしてから講座、の方が自然である。
- 見込み客インタビューと競合リサーチがないと、サービス設計が自分の都合の仮説のまま固まる。JLC内に高卒採用ニーズがあるので、まずそこで一次情報を取る。

---

## ■改善後イメージ（After）

- プロフィールを読むと、最初に「現場の問題を仕組みに変えてきた人」だと分かる。
- 高卒採用は、方法ゼロの失敗→気づき→同じ仕組み化の転用→成功、と一本で読める。
- 退職・転職は、待遇の一言ではなく、具体の問題と学び、次の行動まで見える。
- 社内SEへの誘いが「信頼の証拠」として生き、在籍中の取り組みと離職の経緯もつながる。
- 独立理由にリアリティがあり、「仕組みで人手不足・高卒採用を解く」仕事への着地が自然。
- 事業側では、講座の完成度より、サービス設計・見込み客・競合・複数実績が前に出ている。

---

## ■やりがちなミス

- やってきたことを全部載せようとして、伝えたい一本線を決めない。
- 「仕組み化」と言いながら、特化と関係ないスキル・経歴を同じ分量で並べる。
- 退職理由を待遇・環境のラベルで止め、具体と学びを書かない。
- お客様からの信頼エピソードを一文で切り、社内SEの中身を書かない。
- ターニングポイントがないのに、それらしい劇的転換を後から作る（なければ載せない）。
- 実績1件のまま、講座用プロフィールを先に完成させようとする。
- 「家が近い」以外の理由で選ばれる事例を増やさないまま、再現できる仕組みだと主張する。
- ビジネスモデル（誰・何・いくら・期間）を決めずに、プロフィール文章だけ直す。
- 見込み客インタビューと競合リサーチを後回しにして、自分の仮説だけでサービスを決める。

## ■他の案件でも使えるパターン

- **伝えたいことを先に1文で決める。** 経歴・エピソードは、その線に沿うものだけ抜粋する。
- **羅列ではなく抽出。** 情報量を増やすほど伝わる、ではない。
- **専門性は「何をしてきたか」より「どんな問題を、どう再現可能な形に変えたか」で示す。**
- **問題 → 学び → 次の改善行動**で書くと、人となりと信頼が出る。
- **信頼エピソードはきっかけで止めず、その後の期間・内容・離職までつなぐ。**
- **商品（講座）より先に、サービス設計と実績。** 再現できる形になってから教える側に回る。
- **一次情報（見込み客インタビュー）と競合リサーチで、勝てる路線を決めてから言語化する。**
